Setup

Managed agents and a messaging bridge

ENTRY 01 · PREREQUISITES

What you need

A Switch server with managed agents and a messaging bridge. OpenCode on each machine. A read-only GitHub connection for the maintainer, scoped to the project repo.

Run the commands from a local clone of this public repo. Gateway password login must be enabled on the server.

TLS verification stays on

ENTRY 02 · CONNECTION

Gateway login

The default Gateway is the local HTTPS server.

SWITCH_GATEWAY_API
Set SWITCH_GATEWAY_API when the server isn't at that address. A Gateway URL must end in /gateway. Remote URLs must use HTTPS.
SWITCH_GATEWAY_EMAIL
Set SWITCH_GATEWAY_EMAIL to skip the email prompt.
SWITCH_GATEWAY_PASSWORD
Set SWITCH_GATEWAY_PASSWORD in the environment or enter it at the hidden prompt. The password and session cookie aren't written to disk.
SWITCH_CA_FILE / --ca-file PATH
For a private or self-signed Gateway, set SWITCH_CA_FILE or pass --ca-file PATH with a trusted CA certificate. TLS verification stays on.

During real setup, the maintainer command uses opencode/big-pickle by default.

--model MODEL
Pass --model MODEL to select another model.
--machine NAME
Use --machine NAME to choose a controller.
--dry-run
Add --dry-run to any command to print planned requests without calling the API or changing workdirs.

Python 3.9.6 fails at the sample step

ENTRY 03 · PROCEDURE 01 · SOLO

Solo (one person, about 5 minutes)

Use this mode when one person owns both agents. It deploys a maintainer and one volunteer, checks both configs, and uses owner-agents addressing without a policy update.

  1. scripts/elsewhere solo --project my-project --repo OWNER/NAME

  2. Pass --machine NAME to place both agents on a specific controller.

  3. For the bundled sample, macOS system Python 3.9.6 fails at the pattern-matching step. Python 3.10 or newer passes.

  4. Paste the printed request into the kickoff thread after setup is ready. It mentions both agents.

Config before any session

ENTRY 04 · PROCEDURE 02 · REAL SETUP

Real setup

  1. The maintainer deploys the room and its agent. The command prints a room name, an invite line, and a request message for the kickoff thread.

    scripts/elsewhere maintainer --project my-project --repo OWNER/NAME
    --machine NAME / --model MODEL
    If needed, add --machine NAME to select a controller and --model MODEL to choose a model.

    The maintainer workdir is separate from the project checkout and must contain only opencode.json.

  2. Each volunteer runs one command on their own machine with a unique lowercase handle.

    scripts/elsewhere volunteer --join JOIN_CODE --handle volunteer-1
    --machine NAME
    Volunteers can add --machine NAME to select a controller.

    The command clones this public repo into the empty workdir before any session, checks the effective OpenCode permissions, and confirms there isn't an existing session. It then adds only the maintainer agent and linked messaging identity to the room's addressing policy.

    The join code contains the project slug and Switch IDs. It isn't an access credential. A volunteer must sign in to an account that can access the room.

Keep the exchange in the thread

ENTRY 05 · RUNNING A TEST

Running a test

After everyone is ready, paste the printed request into the kickoff thread. Keep the exact wording and always @mention the maintainer. Keep reports, clarifications, approvals, and rerun results in that thread. Mention the maintainer in every human reply that asks a question or approves an option.

The printed request names sample/QUICKSTART.md and sample/hello.py. The maintainer may read those files without asking and must ask before reading any other source path. Volunteers send every requested result to the maintainer with a targeted message and also post it in the thread.

Redeploy with a fresh slug

ENTRY 06 · TROUBLESHOOTING

Troubleshooting

Certificate errors

Certificate
Set SWITCH_CA_FILE or pass --ca-file PATH with the trusted CA certificate. Don't turn off TLS verification.

A reply didn't reach the maintainer

Replies without an @mention may not be delivered to the agent. Mention the maintainer in each approval or clarification. Volunteers should send results with a targeted message as well as posting in the thread.

A session started before config was ready

Don't use a session that started before the workdir config was placed. Redeploy with a new project slug, then post the kickoff request after setup is ready.
